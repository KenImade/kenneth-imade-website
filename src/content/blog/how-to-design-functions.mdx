A lot of times when I am faced with the task of writing software, I don't necessarily
take the required time to actually **think about what I'm about to write**. I usually
have this bias that I am able to one-shot the function or solution in one go, but recently
I've realized that this is not the case.

For this reason, I've decided to take out time to actually learn how to design functions and in
broader terms, software applications as a whole. However, this article will just be focused on the
nuances around designing function as I believe the best way to show that you understand something is to
talk about it.

## The Function Design Process

At the basic level a well-designed function is meant to take in a particular input and return a particular
output.

- function signature
- purpose of the function
- stub of the function
- Test cases
- Function Template
- Function body
